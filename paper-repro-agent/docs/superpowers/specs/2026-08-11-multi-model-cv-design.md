# 多模型实验与训练集内交叉验证设计

- 日期：2026-08-11
- 状态：方案已获用户确认，待文档复核后实施
- 范围：`paper-repro-agent` 实验服务与对应 Dify 工作流

## 1. 背景与目标

当前实验服务只支持随机森林，并在一次固定的分层 80/20 切分上训练一个模型。目标是增加一组可复现的模型实验，让所有模型使用同一份数据清洗结果和同一份外部测试集，同时只在训练集内部进行交叉验证和超参数选择。

本次升级要回答两个不同问题：

1. 哪个模型在当前数据上的预测能力最好；
2. 哪个模型的指标数值最接近论文报告值。

“接近论文”只表示数值参考比较；当数据集身份、划分方式或阈值不一致时，报告必须继续标记为非严格复现。

## 2. 设计目标

- 支持 Logistic Regression、Random Forest、XGBoost、LightGBM、SVM、KNN 和简单神经网络（`MLPClassifier`）。
- 所有模型共享同一个清洗后的数据集、分层外部测试集、`test_size` 和 `random_state`。
- 交叉验证只发生在外部训练集内，避免测试集信息泄漏。
- 保留当前单随机森林接口和结果格式，已有调用不需要迁移。
- 一次多模型实验中，单个模型失败不能阻断其他模型。
- 输出 AUC、Accuracy、Balanced Accuracy、Precision、Recall、F1、混淆矩阵、训练耗时和模型状态。
- 对论文选中的同名指标计算绝对差异和相对差异，并分别生成性能排名和论文接近度排名。

## 3. 非目标

- 第一版不保存模型二进制、不提供在线预测接口。
- 第一版不把 GPU 作为必需条件；默认 CPU，保持环境和结果可复现。
- 第一版不进行大规模 AutoML、集成投票或堆叠模型。
- 第一版不把论文全体样本上的指标误称为当前 80/20 测试集上的严格复现结果。

## 4. 推荐方案与架构

采用“单次请求内顺序执行模型套件”的方式，而不是在 Dify 中为每个模型复制一套工作流。

```text
CSV 验证与可选去重
        ↓
一次分层外部切分（80/20，seed=42）
        ↓
对每个模型：训练集内 5 折 StratifiedKFold
        ↓
按 CV 评分选择参数，并在完整训练集上重训
        ↓
在同一个外部测试集上统一评估
        ↓
模型结果、性能排名、论文差异排名
```

新增多模型实验入口（命名为 `/v1/run-model-suite`），原有 `/v1/run-experiment` 继续只运行随机森林，以保持向后兼容。多模型入口使用一个整体幂等键、一个整体实验 ID 和一个整体存储结果。

## 5. 输入配置

多模型实验配置包含：

| 配置 | 默认值 | 说明 |
|---|---:|---|
| `models` | 七个模型全部启用 | 可传模型名称列表，便于快速试跑 |
| `target_column` | `Y_cls` | 保持当前默认目标列 |
| `test_size` | `0.2` | 外部测试集比例 |
| `random_state` | `42` | 外部切分和模型随机性的统一种子 |
| `drop_duplicates` | `false` | 与现有接口一致；可单独做去重敏感性实验 |
| `cv_folds` | `5` | 只作用于外部训练集 |
| `optimization_metric` | `roc_auc` | 可选 `roc_auc`、`f1`、`recall`、`balanced_accuracy` |
| `threshold` | `0.5` | 与论文阈值比较时使用固定阈值 |
| `n_iter` | `8` | 每个模型的有限随机搜索次数 |
| `use_gpu` | `false` | 第一版保留字段，默认不启用 |

交叉验证使用 `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)`。所有标准化步骤放入模型自己的 `Pipeline`，确保每个 CV 折只用该折训练部分拟合缩放参数。

## 6. 模型注册与默认处理

模型通过统一注册表提供名称、构建器、预处理器、参数搜索空间和能力信息，避免在 API、引擎和报告中重复写模型分支。

| 模型 | 默认实现 | 处理规则 |
|---|---|---|
| `logistic_regression` | `LogisticRegression` | `StandardScaler`；支持 `class_weight="balanced"` |
| `random_forest` | 现有 `RandomForestClassifier` | 保留类别平衡和随机种子 |
| `xgboost` | `XGBClassifier` | 使用训练集类别比例设置 `scale_pos_weight` |
| `lightgbm` | `LGBMClassifier` | 使用训练集类别比例设置类别权重 |
| `svm` | `SVC(probability=True)` | `StandardScaler`；类别平衡；限制搜索规模 |
| `knn` | `KNeighborsClassifier` | `StandardScaler`；搜索邻居数和距离权重 |
| `mlp` | `MLPClassifier` | `StandardScaler`；早停；限制隐藏层规模 |

XGBoost 和 LightGBM 将作为运行依赖加入服务镜像。若某个部署环境尚未安装对应依赖，套件结果应记录该模型为 `unavailable` 并继续其他模型；正式验收环境必须具备七个模型依赖。

第一版统一使用小规模 `RandomizedSearchCV`，每个模型最多 8 组参数，评分默认使用 ROC-AUC。参数搜索仅访问外部训练集；外部测试集只使用一次。模型的最终测试指标仍统一以阈值 0.5 计算，以便和论文表格比较。

## 7. 结果与排名

新增 `ExperimentSuiteResult`，包括：

- 套件实验 ID和配置；
- 原始数据集画像与去重后的有效行数；
- 共享外部切分信息和 `test_digest`；
- 每个模型的状态、最佳 CV 分数、最佳参数、测试指标、耗时和错误信息；
- 预测性能排名；
- 论文指标差异排名。

每个模型至少返回：

```text
model
status
cv_best_score
roc_auc
accuracy
balanced_accuracy
precision
recall
f1
confusion_matrix
fit_seconds
feature_importance（有能力时提供）
```

性能排名默认按 `roc_auc` 降序，再按 `f1` 和 `recall` 降序。论文接近度排名使用论文中通过 `metric_overrides_json` 选中的同名指标，按绝对差异升序；同时保留相对差异。若论文指标属于随机森林而当前行是其他模型，报告明确标注 `paper_reference_method=random_forest`，不把它解释为其他模型复现了论文方法。

比较模块必须区分三种情况：

1. `paper_metric_missing`：论文没有可用指标；
2. `dataset_or_protocol_mismatch`：论文指标存在，但数据集、样本数量、切分或阈值不一致；
3. `strictly_comparable`：数据集身份和评估协议均一致。

当前奉节数据应保留“参考比较”状态，因为论文描述的 1520/15200 样本与当前 CSV 的 1380/13800 类别计数不一致，且论文指标是全体样本、当前实验是外部测试集。

## 8. Dify 工作流调整

保留现有 PDF 解析、CSV 验证和论文指标覆盖输入。实验节点改为调用多模型套件入口，并增加以下输入：

- 模型列表（默认七个模型）；
- CV 折数；
- 优化指标；
- 是否去重；
- 论文比较阈值。

为了兼容现有输出节点，`experiment_json` 承载套件结果，`comparison_json` 承载每个模型的论文差异，`assessment_json` 承载排名和状态，`markdown_report` 展示最终表格。现有六个字符串输出不改变。

报告中必须显示：共享测试集信息、每个模型的 CV 分数、测试指标、失败原因、论文参考指标、差异和两个排名。任何模型失败都不能让工作流回到 `invalid_dossier` 或输出空对象。

## 9. 错误处理与资源控制

- 数据验证失败：整个套件不启动，返回现有结构化数据错误。
- 单模型依赖缺失或训练失败：该模型状态为 `unavailable` 或 `failed`，记录安全错误码，其余模型继续。
- CV 折数不满足少数类样本量：在启动训练前返回明确的配置错误。
- 训练按模型顺序执行，完成一个模型后释放估计器引用，避免七个模型同时占用内存。
- 默认 CPU；XGBoost/LightGBM 的线程数和搜索次数受配置限制，避免在 16 GB 内存环境中产生过度并发。
- 结果只保存聚合画像、指标、参数和摘要，不保存 CSV 原始行或测试样本内容。

## 10. 测试与验收标准

单元测试覆盖：

- 七个模型名称均能解析并生成对应管道；
- 所有模型收到相同的外部切分索引和 `test_digest`；
- 标准化不泄漏到外部测试集；
- 固定配置重复运行得到相同的四舍五入指标；
- 论文差异排名和性能排名顺序正确；
- 单个模型失败时套件仍能完成；
- 缺失 XGBoost/LightGBM 依赖时返回可读状态；
- 旧随机森林接口测试全部保持通过。

真实 CSV 验收要求：

- 七个模型全部产生结果或清晰的不可用状态；
- 所有成功模型共享同一个外部测试集摘要；
- 报告同时显示 AUC、Accuracy、F1、Recall 和论文差异；
- 去重开关的两次实验互不覆盖，且结果中能看到有效行数变化；
- 论文样本数和当前 CSV 不一致时，报告显示“数据集或协议不一致”，不显示严格复现等级。

## 11. 分阶段实施

1. 增加模型注册表、套件配置和结果模型。
2. 抽取共享切分逻辑，保留旧随机森林基线。
3. 实现训练集内 5 折有限随机搜索和七个模型适配器。
4. 增加套件 API、幂等存储和单模型失败隔离。
5. 扩展论文比较与双排名报告，并修正当前误报“缺少数据集身份”的原因分类。
6. 更新 Dify DSL/节点输入，导入新工作流并进行真实 CSV 验证。
7. 运行完整测试和性能检查后再发布新版本。
