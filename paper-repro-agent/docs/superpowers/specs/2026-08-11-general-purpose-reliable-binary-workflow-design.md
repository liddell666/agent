# 通用论文与表格二分类实验平台设计

- 日期：2026-08-11
- 状态：已获用户批准进入执行
- 范围：普通表格型二分类 CSV；本机单用户；引导式自动配置；多模型实验

## 1. 目标与成功标准

系统面向“任意论文 + 普通表格型二分类 CSV”，让用户上传 PDF 和 CSV 后，先看到机器识别出的实验协议，再确认是否运行。训练任务必须可查看进度、可重试、可恢复，并且不因 Dify 页面关闭或 HTTP 请求超时而丢失结果。

成功标准：

1. 对合规的 UTF-8 表格 CSV，自动完成结构诊断、字段候选识别和风险提示；不把不确定的识别结果静默当成事实。
2. 训练前展示目标列、特征列、数据类型、缺失/重复、类别比例、采样策略、划分方式、交叉验证和指标；用户确认后才提交训练。
3. 所有模型共享同一份外部测试集；超参数搜索和预处理拟合只发生在训练集内部。
4. 任务提交立即返回任务 ID；重启后任务状态和已保存结果仍可查询；单模型失败不会阻塞其他模型。
5. 报告同时提供“预测性能最佳”和“论文结果最接近”两套排名，并解释每套排名的依据。
6. 论文比较只有在指标、数据集、划分和来源条件足够完整时才标记为严格可比；否则标记为部分可比或不可比。

## 2. 非目标与边界

第一阶段不支持多分类、回归、栅格/矢量 GIS 文件、在线预测服务和大规模 AutoML。CSV 仍是主要数据入口，但特征列可以包含数值型和低基数类别型字段；高基数文本、原始 ID 和日期字段默认进入风险提示，不直接作为普通特征使用。

第一阶段默认采用本机单用户、单任务串行执行，以适配 16 GB 内存环境。模型依赖缺失时记录 `unavailable`，继续运行其他模型，并在报告中明确列出。

## 3. 总体架构

系统划分为六个边界：

1. **Dify 交互层**：上传文件、显示诊断预览、收集确认、轮询任务状态和展示报告。
2. **论文解析器**：PDF 转 dossier；保留页码证据、指标限定条件和无法确认的字段。
3. **数据诊断器**：读取 CSV，识别编码/分隔符、列类型、目标候选、缺失、重复、类别失衡、ID 和潜在泄漏。
4. **实验协议生成器**：将论文信息、数据诊断和用户选择生成不可变协议 manifest。
5. **持久化任务引擎**：创建、排队、执行、重试、取消和恢复任务；后台执行模型套件。
6. **比较与报告模块**：输出实验指标、双排名、论文差异、证据链和可比性状态。

数据流：

`上传 PDF/CSV → 自动诊断 → 生成协议草案 → 用户确认 → 创建任务 → 后台训练 → 保存结果 → 双排名报告`

Dify 不再同步等待完整训练；它只负责创建任务和轮询状态。当前同步 API 继续保留，用于兼容现有工作流和回归验证。

## 4. 输入诊断与实验协议

### 4.1 CSV 诊断

诊断结果包含原始文件指纹、行列数、列名、推断类型、目标候选、缺失值、重复行、类别计数/比例、常量列、疑似 ID 列、疑似泄漏列和可用模型条件。

默认规则：

- 目标列必须最终由用户确认，不能只依赖名称猜测。
- 二分类目标必须包含恰好两个类别，且每类样本数满足所选交叉验证折数。
- 数值列直接进入数值预处理；类别列进入训练折内拟合的编码器。
- 缺失值必须显示处理策略。用户可选择拒绝、删除行或训练折内填补；系统不得静默删除数据。
- ID、行号、坐标标识、目标派生列等疑似泄漏字段默认不进入模型，用户可明确恢复。
- 重复行默认给出警告；论文可比模式和稳健验证模式分别记录是否去重及有效行数。

### 4.2 协议 manifest

确认后的 manifest 至少包含：

- PDF dossier 指纹和证据版本；
- CSV 内容指纹、目标列、最终特征列及字段类型；
- 缺失值、类别编码、标准化、去重和采样策略；
- 外部测试比例、随机种子、划分方式、CV 折数；
- 优化指标、决策阈值、模型列表和搜索预算；
- 论文参考指标及其 dataset/split/来源限定；
- 软件版本、依赖版本和任务创建时间。

manifest 创建后不可被训练过程隐式修改。任何改动都生成新的协议和新的任务指纹。

### 4.3 两种实验模式

- **论文可比模式**：尽量复制论文的样本比例、特征和评估协议；缺少论文信息时明确列出缺口。
- **实际预测模式**：保留真实类别分布，允许类别权重、阈值和业务优先级独立配置。

两种模式分别报告，不能把实际预测模式的结果伪装成严格论文复现。

## 5. 模型与评价

保留 Logistic Regression、Random Forest、XGBoost、LightGBM、SVM、KNN 和 MLP 七个模型的统一注册接口。每个模型必须声明预处理、搜索空间、可选依赖、资源上限和特征重要性能力。

所有模型遵循同一协议：

1. 先进行一次固定的分层外部划分。
2. 只在训练集内部进行预处理拟合、5 折交叉验证和有限超参数搜索。
3. 使用最优配置在完整训练集重训。
4. 在同一测试集上计算 AUC、Accuracy、Balanced Accuracy、Precision、Recall、F1、混淆矩阵和训练耗时。
5. 根据用户选择的主指标生成性能排名，并单独生成论文接近度排名。

论文接近度只使用具有完整限定条件的指标。比较请求必须保留 `name`、`reported_value`、`dataset`、`split` 以及可用的 dataset/split provenance；如果任一层丢失条件，报告原因而不是给出“严格可比”。

模型选择不只看 Accuracy：类别失衡时同时展示 Balanced Accuracy、Recall、Precision、F1 和混淆矩阵；必要时提供阈值敏感性结果。报告明确区分“数值接近论文”和“实验协议一致”。

## 6. 持久化任务与恢复

使用本地 SQLite 保存任务元数据，使用受控结果目录保存协议、状态快照和聚合结果。任务状态包括 `queued`、`running`、`succeeded`、`partial`、`failed`、`cancelled` 和 `needs_retry`。

任务执行要求：

- 创建任务时立即返回任务 ID 和协议摘要；
- 单用户环境只允许一个训练任务占用资源，重复提交相同指纹可复用已有任务；
- 每完成一个阶段和一个模型就保存状态，记录进度、耗时和错误码；
- 进程重启后，未完成任务进入 `needs_retry`，已完成模型结果保留；
- 训练异常只隔离当前模型，套件继续执行；
- 支持取消排队任务和请求停止正在运行的任务；
- 只保存聚合指标、配置和指纹，不保存不必要的原始样本内容。

建议接口：

- `POST /v1/jobs`：创建任务并返回任务 ID；
- `GET /v1/jobs/{job_id}`：查询状态、进度和阶段；
- `POST /v1/jobs/{job_id}/cancel`：取消任务；
- `GET /v1/jobs/{job_id}/result`：读取最终结果；
- 旧的 `/v1/run-experiment` 和 `/v1/run-model-suite` 保持兼容。

## 7. 报告设计

报告分为四层：

1. **输入摘要**：论文标题、CSV 指纹、目标列、样本量、特征数、缺失/重复/类别比例。
2. **协议摘要**：预处理、采样、划分、CV、阈值、模型和软件版本。
3. **模型结果**：每个模型的 CV 分数、测试指标、混淆矩阵、最优参数、耗时、特征重要性和失败原因。
4. **比较结论**：性能排名、论文接近度排名、严格/部分/不可比状态、影响结论的警告和下一步建议。

推荐模型必须分别给出：

- 预测性能最佳：按照用户选定主指标并结合关键辅助指标；
- 论文结果最接近：按照绝对差异和相对差异，但只在可比等级允许时使用。

## 8. 实施阶段

### 阶段 1：先修复当前链路并建立协议预览

修复论文指标限定条件在 Dify 比较节点中丢失的问题；增加目标列、类别比例、重复行、疑似 ID 和采样方式的预览；保留当前多模型接口。

### 阶段 2：增强 CSV 适配器

增加分隔符/编码诊断、数值与低基数类别处理、缺失值策略、泄漏提示和用户确认后的最终特征清单。

### 阶段 3：加入持久化任务引擎

实现任务表、状态快照、进度查询、单任务资源限制、重试/取消/恢复和 Dify 轮询工作流。

### 阶段 4：统一实验协议与双排名报告

把所有输入和运行参数写入 manifest；实现性能排名、论文接近度排名、可比性等级和协议差异报告。

### 阶段 5：真实数据验收与稳定性加固

使用当前奉节数据、一个类别型 CSV、一个缺失值 CSV、一个不平衡 CSV 和一个不满足二分类条件的 CSV 做端到端验收；验证重复提交、服务重启、单模型失败、任务取消和长任务恢复。

## 9. 验收标准

- 新论文和合规二分类 CSV 可以在不改代码的情况下完成诊断和配置；
- 用户可以在运行前看到并确认关键实验条件；
- 长任务不会依赖 Dify HTTP 请求持续存活；
- 服务重启后任务状态和已完成结果可恢复；
- 一个模型失败不影响其他模型结果；
- 论文比较不会丢失限定条件，也不会把缺少协议的结果标记为严格复现；
- 同一 manifest、数据指纹、代码版本和随机种子能够复现实验；
- 报告同时给出性能最佳模型和论文最接近模型，并解释二者可能不同的原因。
