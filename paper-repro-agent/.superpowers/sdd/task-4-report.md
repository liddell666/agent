## Implementation notes

- The merged Start includes `run_mode`, optional `paper_pdf`, required `training_csv`, `protocol_token`, `confirm_protocol`, run options, and `protocol_notes`; it does not include `paper_dossier_json`.
- Prepare mode parses PDF, validates parser output, extracts/validates dossier, diagnoses CSV, prepares protocol artifacts, POSTs `/v1/protocol-drafts`, normalizes the response with expected `manifest_draft` metadata, gates on `draft_saved_ok`, and returns preview/token/expiry via `Output_prepare`.
- Run mode confirms the token, GETs `/v1/protocol-drafts/{draft_id}` using `X-Protocol-Token: {{#Start.protocol_token#}}`, normalizes and validates stored draft metadata, validates CSV, submits `/v1/jobs`, polls `/v1/jobs/{job_id}/wait-result`, compares suite results, formats the six report fields, and returns them through `Output_run`.
- Run-branch static tests assert no `paper_pdf`, `paper_dossier_json`, or prepare dossier extraction node references.
- The merged generated YAML splits the literal `sk-` sentinel inside embedded code as `"s" + "k-"` so code still compiles while the serialized DSL does not contain secret-looking tokens.
- Existing `build_multimodel_dsl()` and `build_prepare_dsl()` remain importable and are still generated by the script entrypoint.
